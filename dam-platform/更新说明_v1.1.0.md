# 数据资产管理平台 v1.1.0 更新说明

- 发布日期：2026-11-02
- 生产修复版：2026-11-03（含 Schema 500 修复、血缘卡片、AI 工作台四页签）
- 适用环境：内网 Kylin V10 x86_64 / 外部 PostgreSQL·TBase（10.162.3.16:11001/damplatform）
- 升级方式：数据库脚本 + 环境变量 + 替换后端 jar / 前端 dist

---

## 一、功能更新

### 1. 元数据管理

- 左侧导航拆为「元数据类型 / 数据源（Schema）」两级：
  - 数据表、视图、文件、API、报表分类常驻；
  - 数据源层级优先，源库表不再依赖 `ods_/dwd_` 前缀判断层级；
- 数据表列表新增「分层」列；
- 点击左侧 Schema 可按 Schema 过滤右侧表；
- 单表新增「AI 注释」入口：生成草稿后到 AI 任务中心审核。

### 2. 数据血缘

- 图谱节点按源库/ODS/DWD/DIM/DWS/ADS/报表分层着色；
- 六列泳道布局（DIM 合并到 DWD 列）；
- 支持 1–10 跳、按层级过滤、仅跨层、上下游方向；
- 图谱节点返回 `layer`，边返回 `sourceLayer/targetLayer/isCrossLayer`；
- 中文检索：按字段注释/表注释/字段名/表名搜索，返回相关报表与数据表；
- `parse-sql` 改为注册血缘节点并写 `metadata_lineage_hierarchy`，不再使用表名哈希；
- 引入 JSqlParser，INSERT/CTAS 可解析多表 JOIN/子查询源表；
- 执行记录/字段级 ETL 血缘补全。

### 3. AI 任务中心

- 新增 `dam_asset.ai_task` / `ai_task_item`；
- `/agent` 改为「AI 工作台」：任务中心 + 智能助手；
- AI 注释/分类改为**草稿模式**：先生成任务明细，人工采纳后写回表/资产；
- 数据源级 AI 改为**异步后台任务**，前端轮询状态，不再长请求；
- 任务明细分页、状态筛选、批量采纳/驳回；
- 任务归属校验：只能查看/审核自己创建的任务；
- AI 接口按用户/IP 限流。

### 4. 模型管理

- 页面重构：搜索/状态筛选/统计/字段编辑；
- 字段支持来源表/字段、主键/外键、引用维度、转换规则；
- 字段编辑/删除、DDL 预览/复制/下载；
- 模型复制、JSON 导入/导出、字段上移/下移；
- 修复删除字段 API 路径错误、PK/FK 不落库问题。

### 5. 数据标准

- 统计卡：标准数/已发布/草稿/映射数/覆盖率；
- 标准新建/编辑/发布/归档/删除；
- 值域新增/编辑/删除；字段映射新增/删除；
- 自动校验入口；
- 详情导出（含值域 + 映射）。

### 6. 数据质量

- 规则模板（非空/唯一/枚举/范围/时效/正则）；
- 目标表/字段选择，支持条件式或完整 SELECT；
- 检测记录使用真实通过率/异常数/结果状态/失败样例；
- 趋势按规则、7/30/90 天筛选；
- 修复质量规则执行：
  - 条件式表达式按目标表补全；
  - 总记录数/异常数统计算法修正；
  - SQL 安全校验在补全后执行。

### 7. 安全管控

- 新增 ABAC 数据权限页签：策略新增/编辑/删除；
- 新增数据访问申请页签：申请、批准/拒绝；
- 保留敏感规则、脱敏策略、审计日志、脱敏预览。

### 8. 生命周期

- 策略新增/编辑/启停；
- 策略命中资产预览（执行前确认影响范围）；
- 销毁申请/审批；
- 分层分布 + 执行分层；
- 新增执行记录（归档/销毁/通知），可选表 `metadata_lifecycle_execution`。

### 9. 工单中心

- 工单统计、筛选、新建、分页；
- 工单详情：SLA、指派、状态流转、处理记录/评论；
- 列表显示 SLA 超期；
- 状态流转自动写入处理记录。

### 10. 资产目录 / 详情

- 资产列表：数据源/标签/排序筛选，批量打标签，CSV 导出，列显隐配置；
- 资产详情：概况卡、基本信息/字段/标签评价三页签；

### 12. 2026-11-03 生产修复

- 修复「选择 Schema 后 500」：
  - `asset_info` 没有 `schema_name` 列，原查询直接按 `schema_name` 过滤会生成非法 SQL；

- 新增 `v8_schema_backfill.sql`：单 Schema 数据源的历史数据修复。

  - 画布高度随节点数增长。
- 字段级血缘改为按来源表分组的映射卡片，支持关键字/来源表/目标表筛选，避免字段过多挤在一起。

## 二、安全修复

1. **网关 JWT 验签**
   - `dam-gateway` 改为 `StpLogicJwtForStateless` + `StpUtil.checkLogin()`；
   - 签名错误/过期/伪造 token 返回 401；
   - 所有服务使用统一的 `SA_TOKEN_JWT_SECRET_KEY`。
2. **密钥外置**
   - 数据库口令：`SPRING_DATASOURCE_PASSWORD`；
   - JWT：`SA_TOKEN_JWT_SECRET_KEY`；
   - 智能体 Key：`DAM_AGENT_CHAT_API_KEY` / `DAM_AGENT_CODE_API_KEY`；
   - 不再写死在 `application-*.yml`。
3. **CORS 收紧**
   - 由 `*` 改为 `DAM_CORS_ORIGINS` 指定来源。
4. **任务越权修复**
   - AI 任务按创建人隔离；
   - reviewer 取登录身份，不再落 `system`。
5. **AI 限流**
   - 注释/分类、单表注释、任务创建/审核按用户/IP 限流。
6. **依赖审计**
   - `npm audit --omit=dev`：生产依赖 0 漏洞；
   - dev 依赖剩余 3 个 moderate（`vue-tsc` 的 `minimatch`），不进入运行时。

- `SA_TOKEN_JWT_SECRET_KEY`；

## 五、升级操作步骤（详细）

> 建议在维护窗口执行，预计 20–40 分钟。  
> 升级会重启服务，并让所有旧 token 失效，用户需要重新登录。

### 0. 准备

- 以 `root` 登录服务器 A；
- 确认 A/B 包已上传：
  - `dam-app-A-20261104.tar.gz`
  - `dam-web-B-20261104.tar.gz`
- 备份当前运行版本：

```bash
cp -a /opt/dam /opt/dam.bak-$(date +%Y%m%d%H%M)
cp -a /var/www/dam /var/www/dam.bak-$(date +%Y%m%d%H%M) 2>/dev/null || true
```

### 1. 备份数据库

```bash
export PGPASSWORD='<现有数据库口令>'
mkdir -p /backup/dam-20261104
pg_dump -h 10.162.3.16 -p 11001 -U dam -d damplatform -Fc \
  -f /backup/dam-20261104/damplatform-before-v1.1.0.dump
```

至少确认备份文件存在且大小正常：

```bash
ls -lh /backup/dam-20261104/damplatform-before-v1.1.0.dump
```

### 2. 生成 JWT 密钥并更新环境变量

```bash
SECRET="$(openssl rand -base64 48)"
sed -i "s|^SA_TOKEN_JWT_SECRET_KEY=.*|SA_TOKEN_JWT_SECRET_KEY=${SECRET}|" /etc/dam/env.conf
chmod 600 /etc/dam/env.conf
```

确认长度正确（不要直接把密钥打印出来）：

```bash
awk -F= '/^SA_TOKEN_JWT_SECRET_KEY=/{print "JWT length=" length($2)}' /etc/dam/env.conf
```

然后编辑 `/etc/dam/env.conf`，确认以下项都已替换：

```bash
vi /etc/dam/env.conf
```

必须修改/确认：

```bash
SPRING_DATASOURCE_PASSWORD=<新的数据库口令>
SA_TOKEN_JWT_SECRET_KEY=<上一步生成的值，所有服务一致>
DAM_CORS_ORIGINS=http://<服务器B的IP>
DAM_AGENT_CHAT_API_KEY=<新的 LLM Key>
DAM_AGENT_CODE_API_KEY=<新的 LLM Key>
```

检查不能残留 `CHANGE_ME`：

```bash
grep -n 'CHANGE_ME' /etc/dam/env.conf || echo 'env ok'
```

> `DAM_SECURITY_CRYPTO_SECRET` 不要改：它必须与现有库中数据源口令的加密密钥一致。

### 3. 执行数据库迁移

先加载环境变量：

```bash
set -a
. /etc/dam/env.conf
set +a
export PGPASSWORD="$SPRING_DATASOURCE_PASSWORD"
cd /opt/dam-app-A/db
```

按顺序执行：

```bash
# 1) 血缘层级列（必须）
psql -h 10.162.3.16 -p 11001 -U dam -d damplatform \
  -v ON_ERROR_STOP=1 -f v4_lineage_layers.sql

# 2) AI 任务表（使用 AI 任务中心必须）
psql -h 10.162.3.16 -p 11001 -U dam -d damplatform \
  -v ON_ERROR_STOP=1 -f v5_ai_tasks.sql

# 3) 血缘 node_key：先只读预检
psql -h 10.162.3.16 -p 11001 -U dam -d damplatform \
  -v ON_ERROR_STOP=1 -f v6_lineage_identity_precheck.sql
```

确认预检结果后，再执行 v6：

```bash
psql -h 10.162.3.16 -p 11001 -U dam -d damplatform \
  -v ON_ERROR_STOP=1 -f v6_lineage_identity.sql
```

> v6 的注意事项见 `db/v6_lineage_identity_README.md`；不要用 `BEGIN/COMMIT` 包住脚本。

可选：生命周期执行记录表：

```bash
psql -h 10.162.3.16 -p 11001 -U dam -d damplatform \
  -v ON_ERROR_STOP=1 -f v7_lifecycle_execution.sql
```

如果历史资产没有保存 schema_id，再执行：

```bash
psql -h 10.162.3.16 -p 11001 -U dam -d damplatform \
  -v ON_ERROR_STOP=1 -f v8_schema_backfill.sql
```

> v8 只处理「一个数据源只有一个 Schema」的情况；多 Schema 请按 Schema 重新扫描/注册。

### 4. 更新服务器 A 后端

```bash
tar xzf /path/to/dam-app-A-20261104.tar.gz -C /opt
cd /opt/dam-app-A
bash scripts/install-app.sh
```

说明：

- 安装脚本会拷贝 10 个新 jar 并按顺序重启服务；
- 如果 `/etc/dam/env.conf` 已存在，脚本**不会覆盖**，需要你提前按第 2 步修改；
- 如果脚本提示 `CHANGE_ME` 未替换，先修改 env 再重新执行。

### 5. 更新服务器 B 前端

```bash
tar xzf /path/to/dam-web-B-20261104.tar.gz -C /opt
cd /opt/dam-web-B
bash scripts/install-frontend.sh <服务器A的IP>
```

### 6. 手动重启（如果安装脚本未重启）

```bash
for s in auth gateway catalog lineage standard quality security lifecycle operations agent; do
  systemctl restart "dam@dam-$s"
  sleep 1
done
```

顺序必须是 `auth` → `gateway` → 其余；全部启动后检查：

```bash
systemctl --no-pager --type=service --state=running | grep 'dam@dam-'
```

### 7. 验证

服务器 A：

```bash
bash /opt/dam-app-A/scripts/verify.sh app
```

服务器 B：

```bash
bash /opt/dam-web-B/scripts/verify.sh web <服务器A的IP>
```

重点验证：

1. 无效 token 返回 401：

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  -H 'token: invalid-token' \
  http://127.0.0.1:8080/api/catalog/assets/search
```

预期 `401`。

2. 浏览器打开前端，使用 `admin` 重新登录；
3. 资产目录能加载、能打开资产详情；
4. 数据血缘能打开图谱并显示层级；
5. AI 工作台能创建任务、查看草稿；
6. 质量规则能执行并看到通过率；
7. 生命周期能预览命中资产（v7 已执行时可看执行记录）；
8. 工单能打开详情、状态流转有处理记录。

### 8. 回滚

应用回滚：

```bash
# 后端
rm -rf /opt/dam
mv /opt/dam.bak-<时间戳> /opt/dam
systemctl restart 'dam@dam-auth' 'dam@dam-gateway'
# 其余服务按同样顺序重启

# 前端
rm -rf /var/www/dam
mv /var/www/dam.bak-<时间戳> /var/www/dam
nginx -s reload
```

数据库回滚：

- 仅 v6 需要：执行 `db/v6_lineage_identity_rollback.sql`；
- v4/v5/v7 为新增列/表，保留不影响旧版本；
- 如必须完全恢复，使用第 1 步的 `pg_dump` 备份恢复（会丢失升级后新数据）。

环境变量回滚：

- 恢复旧 `SA_TOKEN_JWT_SECRET_KEY`、数据库口令、LLM Key；
- 重启服务并重新登录。

## 六、兼容性 / 已知限制

- 旧 token 全部失效，必须重新登录；
- 旧 AI 任务 `created_by=system` 不会出现在个人任务列表；
- 异步 AI 任务在服务重启后不会自动恢复，需要重新发起；
- 质量规则执行依赖目标表在当前数据库可访问；
- 血缘节点 schema 限定目前只完成 `node_key` 准备，应用切换需后续版本；
- JSqlParser 只补全表级多表血缘，字段级仍以正则结果为主；
- 限流为单实例内存，多实例部署需换 Redis；
- Java 依赖 CVE 扫描未在内网完成，建议上线前用 OWASP Dependency-Check 离线库补扫。

- 若已切换密钥，回滚后需恢复旧环境变量并重新登录。
