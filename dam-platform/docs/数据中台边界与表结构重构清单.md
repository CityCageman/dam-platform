# 数据中台边界与表结构重构清单

## 0. 结论

不建议推倒重写，也不建议一次性拆成 20 多个微服务。

建议路线：

```text
统一门户先行
  → catalog 包级模块化
  → 表所有权和 schema 迁移
  → 按边界抽服务
  → 补数据工程能力
  → 补主数据、数据服务、数据市场
```

现有表结构不是“全部推倒重来”，而是要做三类重构：

1. **表所有权重构**：解决多个服务共用 schema、重复实体映射同一张表；
2. **schema 重构**：指标、报表、知识、质量、血缘、生命周期从共享 schema 迁出；
3. **公共字段补齐**：租户、组织、审计、版本、状态、数据归属。

不建议大规模改表名和字段名，优先用 `SET SCHEMA`、兼容视图、双读双写过渡。

# 4. 阶段 2：catalog 包级模块化

## 目标

不拆部署，先拆代码边界。

当前 `dam-catalog` 过大，建议包结构：

```text
dam-catalog
├── asset
├── metadata
├── datasource
├── metric
├── report
└── knowledge
```

## 规则

- 模块之间不直接注入对方 Mapper；
- 通过模块 Service 接口调用；
- 公共能力放 common；
- 先不跨库。

## 重点清理重复实体

当前存在同一张表被多个模块实体映射的情况：

| 表 | 重复实体 | 处理 |
|---|---|---|
| metadata_quality_rule | catalog.DamQualityRule / quality.DamQualityRule | 只保留 quality 为写方 |
| metadata_quality_check_result | catalog.DamQualityCheck / quality.DamQualityCheck | 只保留 quality |
| metadata_lineage | catalog.DamLineage / lineage.DamLineage | 只保留 lineage |
| source_system | catalog.DamSourceSystem / lineage.SourceSystem | 只保留 metadata |
| asset_statistics | catalog.AssetStatistics / operations.DamUsageStats | 明确 asset 为写方，operations 只读 |
| metadata_collection | DamMetadataCollection / DamScanJob | 合并为一个实体 |
| metadata_management | DamMetadataExt / MetadataManagement | 合并为一个实体 |

## 验收

- catalog 内模块依赖单向；
- 没有重复 Mapper 写同一张表；
- 旧 API 保持兼容；
- 此阶段不改数据库。

# 5. 阶段 3：表结构和 schema 重构

## 结论

需要重构，但不是全量重写。

### 必须重构

1. 多个服务共用一个 schema；
2. 多个服务写同一张表；
3. 指标、报表、知识仍在 `dam_asset`；
4. 质量、血缘、生命周期仍在 `dam_metadata`；
5. 系统字典/配置由 catalog 持有；
6. 缺少租户、组织、统一审计字段。

### 不需要重构

- 不需要把所有表改名；
- 不需要把所有主键改 UUID；
- 不需要为了微服务把每张表拆开；
- 不需要一次性删除历史字段。

## 迁移步骤

### 3.1 建新 schema 和数据库角色

```text
dam_metric
dam_report
dam_knowledge
dam_quality
dam_lineage
dam_lifecycle
dam_integration
```

每个服务一个账号，只授权自己的 schema。

### 3.2 建兼容视图

旧 schema 建视图指向新表：

```sql
CREATE VIEW dam_asset.metric_definition AS
SELECT * FROM dam_metric.metric_definition;
```

保证旧代码仍可运行。

### 3.3 双读/双写过渡

- 新代码读写新 schema；
- 旧代码读旧视图；
- 观察一段时间；
- 再删除旧表/视图。

### 3.4 迁移表

对独立表使用：

```sql
ALTER TABLE dam_asset.metric_definition SET SCHEMA dam_metric;
```

对共享表：

1. 确定唯一写服务；
2. 其他服务改为 API 调用；
3. 再迁移。

### 3.5 公共字段补齐

建议统一增加：

```text
tenant_id
org_id
owner_id
status
version
created_at
created_by
updated_at
updated_by
deleted_at
```

不建议所有表一次加完，按模块逐个加。

## 验收

- 每个 schema 只有一个写服务；
- 没有跨服务写表；
- 旧接口兼容；
- 数据迁移可回滚；
- 查询性能不下降。

不要做“大爆炸重构”。


# 11. Schema 命名规范

## 结论

**保留 `dam_` 前缀，不要把 `dam` 理解成 DAM 模块本身。**

这里的 `dam_` 应该定义为：

```text
平台命名空间前缀
```

而不是：

```text
DAM 数据资产管理模块
```

## 推荐命名

```text
dam_sys
dam_asset
dam_metadata
dam_metric
dam_report
dam_knowledge
dam_standard
dam_model
dam_quality
dam_lineage
dam_security
dam_lifecycle
dam_integration
dam_mdm
dam_market
dam_ops
dam_ai
```

含义：

| Schema | 归属 |
|---|---|
| dam_sys | 用户、角色、租户、菜单、字典、配置 |
| dam_asset | DAM 资产目录、资产标签、资产关系 |
| dam_metadata | 技术元数据、数据源、扫描、版本 |
| dam_metric | 指标定义、指标值、指标规则 |
| dam_report | 报表、看板、执行记录 |
| dam_knowledge | 知识分类、条目、文档 |
| dam_standard | 标准、码表、映射 |
| dam_model | 主题域、逻辑模型、物理模型 |
| dam_quality | 质量规则、检查、结果 |
| dam_lineage | 表级/字段级血缘、SQL 解析 |
| dam_security | 分类分级、脱敏、权限、审计 |
| dam_lifecycle | 保留、归档、销毁 |
| dam_integration | 连接器、同步任务、位点 |
| dam_mdm | 主数据实体、黄金记录、分发 |
| dam_market | 数据产品、订阅、计量 |
| dam_ops | 工单、运维、SLA |
| dam_ai | AI 任务、对话、Prompt |

## 为什么不改成 `dmp_`

可以改，但不建议现在改。

原因：

1. 所有服务名已经是 `dam-*`；
2. 环境变量已经是 `DAM_*`；
3. Java 包名是 `com.dam`；
4. 现有表、索引、权限、备份都围绕 `dam_`；
5. 改前缀收益只是命名更“像数据中台”，但迁移成本很高。

如果未来产品正式更名为 DMP，可以再做一次独立命名空间迁移：

```text
dam_* → dmp_*
```

通过新 schema + 兼容视图 + 双读过渡，而不是直接全库改名。

## 表名规则

Schema 带平台前缀，表名不要再重复：

推荐：

```text
dam_metric.metric_definition
dam_metric.metric_value
dam_quality.quality_rule
dam_quality.quality_check_result
dam_knowledge.knowledge_entry
```

不推荐：

```text
dam_metric.dam_metric_definition
dam_quality.dam_quality_rule
```

现有少量 `dam_` 开头的表名，例如：

```text
dam_metadata.dam_data_source_type
```

可以在不影响业务的前提下逐步改为：

```text
dam_metadata.data_source_type
```

表名重构优先级低于 schema 归属重构。

## 服务名规则

```text
dam-gateway
dam-auth
dam-portal
dam-metadata
dam-metric
dam-report
dam-knowledge
dam-quality
dam-lineage
dam-security
dam-lifecycle
dam-integration
dam-mdm
```

## 最终约定

```text
dam_      = 平台 namespace
DAM       = 数据资产管理能力域
dam_asset = DAM 模块的数据 schema
```

不要把这两个概念混在一起。
