# DAM 数据中台产品化重构方案

> 版本：V1 方案，待确认后实施  
> 原则：不推倒重来，不做 8 个巨石服务，不继续在旧结构上叠页面。

---

## 一、重构目标

把当前“按能力域堆出来的系统”重构为“可产品化交付的数据中台套件”。

目标不是：

```text
把 19 个服务合并成 8 个服务
重写所有页面
一次性迁移全部数据库
```

目标是：

```text
产品有清晰边界
角色有清晰入口
服务有明确归属
数据有一份权威 schema
功能可独立交付、独立验收
```

---

## 三、8 个产品边界

| 产品 | 负责内容 | 当前服务/模块 | 备注 |
|---|---|---|---|
| 1. 数据资产与主数据 | 资产目录、资产 360、元数据、分类标签、质量评分、MDM | dam-catalog、dam-metadata、未来 dam-mdm | 第一优先 |
| 2. 数据中台管理 | 门户、调度、任务、运维、系统配置、可观测 | dam-portal、dam-scheduler、dam-task-center、dam-operations、dam-sys、未来 dam-observability | 平台产品 |
| 3. 数据接入 | 数据源、连接器、集成任务、抽取执行 | dam-integration（含 access） | 数据源已迁入 |
| 4. 数据治理 | 标准、质量、安全、生命周期、血缘 | dam-standard、dam-quality、dam-security、dam-lifecycle、dam-lineage | 统一治理入口 |
| 5. 数据处理 | 开发、建模、清洗转换、聚合、存储计算 | dam-develop、dam-model、未来 dam-storage | 数据工程 |
| 6. 数据服务 | API 管理、OpenAPI、订阅、限流、审计 | dam-data-service | 已有基础 |
| 7. 数据分析 | 指标、报表、自助分析、可视化 | dam-metric、dam-report、未来分析引擎 | 报表需独立 |
| 8. 数据应用 | 场景应用、数据产品、应用发布、应用运行时 | 未来 dam-app / dam-market | 当前缺失 |

AI 不作为第 9 个产品，作为横切能力：

```text
dam-ai-workbench
dam-model-gateway
dam-knowledge
```

服务对象：

```text
资产：AI 描述/注释/分类
治理：质量/安全/标准智能检查
分析：智能问数/报表生成
应用：AI 应用构建
```

## 五、后端重构目标

### 保留微服务

不合并现有服务，按产品重新归属。

### 新增产品注册能力

建议放在 `dam-sys` 或独立 `dam-product`：

```text
product_definition
product_module
tenant_product
role_product
product_entitlement
role_cockpit
cockpit_widget
```

### API 命名

新接口统一：

```text
/api/{product}/{module}/...
```

现有接口保持兼容，逐步迁移，不一次性改所有路径。

### 内部 API

```text
/internal/...
```

只允许服务间调用，不暴露网关。

## 六、数据层重构

### 当前问题

```text
20 个 schema
76 张实体表
init-all.sql 106 张表，含旧表
create_schema_doc.sql 52 张表，schema 已过期
dam_quality / dam_ai / dam_report 归属不一致
MDM 完全没有表
```

### 目标

```text
一份权威 schema 清单
一套增量迁移
一个迁移账本
一组 schema 契约测试
```

### 目录调整

```text
db/
  bootstrap/      新库初始化，只保留当前权威表
  migrations/     v44 之后增量迁移
  legacy/         旧脚本归档，不再执行
  SCHEMA.md       权威表清单
```

### 先解决的冲突

```text
dam_quality vs dam_metadata.metadata_quality_*
dam_ai vs dam_asset.ai_task*
dam_report vs dam_asset.report_catalog
dam_sys vs dam_system
dam_security vs dam_security_management
dam_ticket vs dam_ticket_center
```

### MDM 新 schema

```text
dam_mdm.md_domain
dam_mdm.md_entity
dam_mdm.md_attribute
dam_mdm.md_record
dam_mdm.md_golden_record
dam_mdm.md_version
dam_mdm.md_distribution
```

### 迁移策略

```text
先修 schema 契约
再建只读兼容视图
再迁数据
最后删旧入口
```

不做一次性大爆炸迁移。

## 九、重构策略

采用绞杀者模式：

```text
旧入口继续可用
新入口逐步接管
数据通过视图/双写过渡
确认无调用后删除旧入口
```

禁止：

```text
一次性重写全部服务
一次性迁移全部表
同时改产品、数据、权限、AI
```

---

## 十、验收标准

产品层：

```text
产品中心按授权显示
产品首页可进入
产品菜单不越权
单窗口
```

服务层：

```text
每个产品有明确服务归属
内部 API 不暴露
现有接口兼容
```

数据层：

```text
新库只使用权威 schema
迁移可重复执行
实体表与数据库列一致
MDM/AI 表归属确定
```

安全：

```text
角色数据范围后端强制
旧 token 处理明确
系统配置仅授权角色
```
