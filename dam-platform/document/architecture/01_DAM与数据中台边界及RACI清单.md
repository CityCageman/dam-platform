# DAM 与数据中台边界及 RACI 清单

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.2（已吸收 2026-11-04 决策） |
| 日期 | 2026-11-04 |
| 适用范围 | 数据资产管理平台（DAM）、新建数据中台 |
| 目标 | 明确两个系统的职责、功能归属、接口边界、协作机制，避免重复建设和各自为战 |
| 状态 | 待架构评审 |

---

## 1. 目的

本文件回答四个问题：

1. 现有 DAM 中哪些功能实际上属于数据中台；
2. 数据中台应该建设哪些能力；
3. DAM 与中台各自保留什么、迁移什么；
4. 两个系统如何通过接口、ID、流程和组织机制关联。

---

## 2. 总体结论

> **数据中台负责数据生产与运行；DAM 负责数据治理与资产运营。**

- **中台**：数据源接入、集成/CDC、ODS/DWD/DIM/DWS/ADS、模型、调度、质量执行、安全执行、数据服务；
- **DAM**：资产目录、业务元数据、数据标准、质量规则、安全策略、血缘展示、生命周期策略、报表目录、运营工单；
- **原则**：同一个对象只能有一个权威方；另一方只读或引用，不跨库直接写入。

### 2.1 已确认决策（2026-11-04）

1. 数据源注册中心、扫描器完全归中台，DAM 不再维护扫描器；
2. 模型设计、DDL、物理属性完全归中台，DAM 只保留模型资产卡片；
3. 质量执行全部归中台，DAM 只保留规则库和结果视图；
4. 策略下发不是单一策略，而是标准、质量规则、安全策略、生命周期策略四类；MVP 先做质量规则 + 安全策略；
5. BIZ 是业务域，不是物理分层；业务域落在 DWS/ADS 资产上；DWD 是否建设待评估；
6. MVP 必须包含字段级元数据同步，不能只同步表名。

### 2.2 仍待确认

- 中台技术选型（SeaTunnel/DataX、DolphinScheduler、Flink CDC）；
- 策略下发用“中台拉取”还是“DAM 推送”（本文默认拉取）；
- 是否引入事件总线；
- 数据源凭证保管和轮换；
- 部署网络和认证方式。

## 3. 术语

| 术语 | 说明 |
|---|---|
| DAM | 数据资产管理平台，治理与资产运营门户 |
| 中台 | 数据中台，数据集成、存储、开发、调度、运行平台 |
| 技术元数据 | 表、字段、类型、分区、作业、运行状态等 |
| 业务元数据 | 业务含义、术语、负责人、标准、安全等级等 |
| 业务域（BIZ） | 门诊、住院、财务等业务主题，不是物理分层；挂在 DWS/ADS 资产上 |
| 单一事实来源 | 某个对象只有一个系统拥有写权限，其他系统引用 |
| 资产 ID | DAM 分配的全局资产标识 `asset_id` |
| 外部键 | 中台侧稳定唯一键 `external_key`，用于幂等注册 |

## 4. 边界原则

1. **数据面 vs 治理面**：数据在中台，治理规则在 DAM。
2. **一个资产目录**：DAM 是唯一面向业务的资产目录，中台不另建业务目录。
3. **一个数据源注册中心**：连接、凭证、采集任务在中台；DAM 只引用 `data_source_id`。
4. **一个模型权威**：模型设计、DDL、物理属性在中台；DAM 只登记模型资产。
5. **一个质量规则库**：规则定义在 DAM，执行在中台，结果回 DAM。
6. **一个血缘图**：中台产生血缘事件，DAM 汇总展示，不各画一套。
7. **一个策略中心**：标准、分级、脱敏、生命周期策略由 DAM 定义，中台执行。
8. **不跨库写数据**：系统之间只通过 API/事件交互。
9. **共享 ID**：资产、数据源、模型、作业、规则、策略必须有稳定 ID。
10. **UI 不重复**：DAM 不做数据开发/调度，中台不做治理审批。

| 数据标准、码值 | 标准治理 | DAM | 保留 |
| 质量规则库、结果展示 | 质量治理 | DAM | 保留规则与结果视图 |
| 安全分级、脱敏策略、访问审批 | 安全治理 | DAM | 保留 |
| 血缘图谱、影响分析 | 血缘治理 | DAM | 保留 |
| 生命周期策略、审批 | 生命周期治理 | DAM | 保留 |
| 报表目录、报表口径 | 报表治理 | DAM | 保留 |
| 工单、运营 | 平台运营 | DAM | 保留 |

| 用户、权限、SSO | 身份 | 共用 | 统一 SSO，各自授权 |

### 5.1 需要特别说明的三个点

#### 元数据采集

- **采集器、连接、扫描任务**属于中台；
- **资产编目、业务注释、标准绑定**属于 DAM；
- DAM 不再维护第二套数据源连接和扫描器。

#### 模型管理

- 严格区分时，**模型设计属于中台**；
- DAM 只保留模型资产卡片、标准、质量、安全、血缘；
- 如果 DAM 继续做完整建模器，就会变成第二个中台。

#### 血缘

- 中台在作业运行时产生血缘；
- DAM 负责汇总、展示、影响分析和人工补充；
- DAM 不把 SQL 解析作为唯一血缘来源。

## 6. 目标功能地图

### 6.1 数据中台

```text
数据源与连接
  └─ 数据集成（批量/CDC）
       └─ ODS
            └─ DWD（是否建设待评估）
                 ├─ DIM
                 └─ DWS（按业务域组织）
                      └─ ADS（按业务域组织）
                           └─ 数据服务 / BI

配套：
  模型设计、数据开发、调度、补数、运行监控
  技术元数据与血缘采集
  质量执行
  安全执行
  数据服务/指标
```

### 6.2 DAM

```text
资产目录
业务元数据/术语
数据标准/码值
质量规则库/结果
安全分级/策略/审批
血缘图谱/影响分析
生命周期策略/审批
报表目录/口径
运营工单
治理看板
```

### 6.3 分层与业务域定义

建议统一层级：

```text
ODS → DWD（待评估） → DIM → DWS → ADS → REPORT
```

- `ODS`：贴源层；
- `DWD`：明细层，是否建设需结合清洗复杂度和时效要求评估；
- `DIM`：公共维度；
- `DWS`：按业务域组织的汇总层；
- `ADS`：按业务域组织的应用层；
- `BIZ` 不是物理分层，而是**业务域属性**，落在 DWS/ADS（以及未来 DWD）资产上；
- DAM 不需要新增 `BIZ` 层级；应增加/复用 `business_domain`（当前可用 `subject_domain`）字段；
- 前端应按“分层”筛选 ODS/DWD/DIM/DWS/ADS，按“业务域”筛选门诊/住院/财务等，不要把业务域做成层级。

### 6.4 策略类型

“策略下发”指 DAM 把治理规则交给中台执行，按对象分为四类：

| 类型 | 内容 | 中台用途 | MVP |
|---|---|---|---|
| `STANDARD` | 数据标准、命名、类型、码值 | 建模/校验参考 | 可先只读同步 |
| `QUALITY_RULE` | 非空、唯一、范围、及时性、SQL 规则、阈值 | 质量执行 | **MVP 必做** |
| `SECURITY_POLICY` | 安全分级、敏感类型、脱敏算法、行级权限 | 查询/服务执行 | **MVP 必做** |
| `LIFECYCLE_POLICY` | 保留期、归档、销毁 | 存储/归档执行 | 二期 |

MVP 不建议一开始把四类全做完；先做质量规则和安全策略两类真正需要运行时执行的策略。

## 8. 数据流与控制流

```text
【控制流】
DAM ──标准/质量规则/安全策略/生命周期策略（MVP：质量+安全）──▶ 中台
中台 ──资产注册/Schema变更/血缘/质量结果/生命周期结果──▶ DAM

【数据流】
源库 ──集成/CDC──▶ ODS ──▶ DWD（待评估） ──▶ DIM ──▶ DWS/ADS（业务域） ──▶ BI/服务
```

要点：

- 控制流和数据流分离；
- 中台不把明细数据推给 DAM；
- DAM 不直接读取中台业务表做质量/统计；
- 质量执行在中台，DAM 只接收结果。

## 10. 接口与 ID 约定

### 10.1 共享 ID

| ID | 分配方 | 用途 |
|---|---|---|
| `data_source_id` | 中台 | 数据源唯一标识 |
| `asset_id` | DAM | 全局资产标识 |
| `model_id` | 中台 | 模型标识 |
| `deployment_id` | 中台 | 模型部署实例 |
| `job_id` / `run_id` | 中台 | 作业/运行实例 |
| `rule_id` | DAM | 质量规则 |
| `policy_id` | DAM | 安全/生命周期策略 |
| `external_key` | 中台 | 资产幂等注册键 |

### 10.2 交互方式

- MVP：REST + 幂等键 + 重试；
- 后续：事件总线/Outbox，可靠投递；
- 禁止：跨库直接写表、共享数据库账号、绕过接口改数据。

### 10.3 元数据同步要求

MVP 必须做到**字段级**：

- 表级：数据源、Schema、表名、表类型、分层、业务域、注释、行数、负责人；
- 字段级：字段名、类型、长度/精度、可空、主键、默认值、注释、序号；
- 支持全量快照 + 增量变更；
- 字段新增/删除/改类型必须能识别；
- 使用 `externalKey` + `schemaHash` 做幂等和漂移检测；
- 中台是技术元数据权威，DAM 只编目和补充业务信息。

详细接口见《02_中台MVP接口契约.md》的 `POST /metadata/sync`。

## 12. 迁移路线

### Phase 0：定边界（1–2 周）

- 评审本清单；
- 确认 RACI；
- 确认接口契约；
- 确认业务域清单；确认 DWD 是否建设。

### Phase 1：中台 MVP（4–8 周）

- 1–2 个源系统；
- 源库 → ODS；
- DolphinScheduler 调度；
- 资产注册到 DAM；
- 基础运行监控。

### Phase 2：模型与质量（6–10 周）

- ODS → DWD（如建设） → DIM/DWS/ADS（按业务域）；
- 模型设计/版本；
- 质量执行；
- 血缘回写；
- 安全策略执行。

### Phase 3：实时与服务（8–12 周）

- 关键表 CDC；
- 数据服务 API；
- 指标体系；
- 数据产品目录。

### 现有 DAM 处理

1. 冻结重叠功能的新增开发；
2. 标记“迁移中/只读”；
3. 迁移数据源、扫描、模型、质量执行、生命周期执行；
4. DAM 保留资产目录、标准、规则、策略、血缘展示；
5. 旧数据保留只读，验证后下线。

---

## 13. 反模式

1. DAM 和中台都能建模型；
2. 两边各有一套数据源和扫描器；
3. DAM 直接跑 ETL/清洗；
4. 中台另建业务资产目录；
5. 两套质量规则/两套评分；
6. 两套血缘图；
7. 两套安全策略；
8. 跨库直接写对方表；
9. 只同步一次元数据，没有变更/对账；
10. DAM 和中台菜单大量重复。

---

## 14. 验收标准

- [ ] 数据源只在中台注册，DAM 只引用；
- [ ] 资产目录只在 DAM，DAM 有全局 `asset_id`；
- [ ] 中台新表能自动注册到 DAM；
- [ ] 字段级元数据支持全量 + 增量同步；
- [ ] Schema 变更能通知 DAM 并做影响分析；
- [ ] 质量规则在 DAM 定义、中台执行、结果回 DAM；
- [ ] 安全策略在 DAM 定义、中台执行；
- [ ] 血缘由中台产生、DAM 展示；
- [ ] 生命周期策略在 DAM、执行在中台；
- [ ] 两边无直接数据库写入；
- [ ] 两边菜单无重复的完整功能模块；
- [ ] SSO 和深链可用；
- [ ] 有接口契约、ID 规范、对账机制。
